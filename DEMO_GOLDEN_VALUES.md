# Customer-support demo golden values

These values are generated by `buildDemoProject()` and are the regression contract for the seeded customer-support demo.

| Assumption | Value |
|---|---:|
| Monthly executions | 100,000 |
| Monthly budget | $12,000 |
| Privacy classification | High |
| Pricing provenance | BuildWise demo catalogue 2026.09, effective 2026-09-08 |
| Tokens | Per task execution unless labelled monthly |

| Scenario | Monthly cost | Input tokens / execution | Cached input tokens / execution | Output tokens / execution | Calls / execution | Savings vs baseline |
|---|---:|---:|---:|---:|---:|---:|
| Baseline | $39,308.23 | 48,438 | 5,382 | 6,706 | 5 | 0.0% |
| Economy | $173.15 | 7,326 | 13,604 | 3,115 | 2 | 99.6% |
| Balanced | $771.27 | 12,707 | 12,708 | 3,832 | 3 | 98.0% |
| Assurance | $24,128.48 | 30,272 | 10,093 | 5,748 | 5 | 38.6% |

These values are derived from distinct execution policies, not target savings: Baseline uses an advanced model for every applicable task with broad context; Economy uses deterministic routing, small-model extraction, strict context and high caching; Balanced uses deterministic routing plus selective small/standard models, filtered retrieval and schema validation; Assurance uses stronger models and dual validation for high-risk work. Economy's high saving reflects the seeded support workload's large deterministic share and is shown with the underlying assumptions in the calculation drawer.

The deterministic policy-retrieval task contributes zero model cost; its retrieval workload remains visible in the trace and is not silently treated as provider usage.
